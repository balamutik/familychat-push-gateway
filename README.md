# Push-шлюз FamilyChat

Отдельный HTTPS-сервис для APNs (сообщения и PushKit/CallKit) и FCM (сообщения, вызовы и состояние вызова). Серверы чатов не получают приватные ключи Apple/Google. Изменение существующих приложений iOS/Android не требуется. Настройки APNs и Firebase должны соответствовать официальной или собственной сборке клиента; один процесс обслуживает один набор приложений и одну APNs-среду. Для development и production используйте отдельные экземпляры.

## Развёртывание шлюза

На отдельном Linux-хосте с Docker Compose:

```bash
git clone https://github.com/balamutik/familychat-push-gateway.git
cd familychat-push-gateway
```

Подготовьте каталоги и настройки:

```bash
sudo install -d -m 0700 -o 10001 -g 10001 data secrets export
cp .env.example .env
chmod 600 .env
```

В `.env` укажите Key ID, Team ID, Bundle ID и/или Firebase Project ID и Android application ID. Скопируйте ключи **только на этот хост**, используя нужные строки:

```bash
sudo install -m 0400 -o 10001 -g 10001 /root/AuthKey.p8 secrets/apns.p8
sudo install -m 0400 -o 10001 -g 10001 /root/firebase-service-account.json secrets/fcm.json
sudo install -m 0400 -o 10001 -g 10001 /path/to/fullchain.pem secrets/tls.crt
sudo install -m 0400 -o 10001 -g 10001 /path/to/privkey.pem secrets/tls.key
sudo docker compose build gateway
sudo docker compose up -d gateway
```

Нужен действующий TLS-сертификат для имени шлюза от доверенного центра сертификации. DNS и входящий порт 9443 должны быть доступны серверу чатов. Выпуск и продление сертификата выполняются вашим ACME-клиентом; после продления копируйте пару в `secrets`. Сервис перечитывает TLS-файлы при новом handshake. Не заменяйте эту настройку отключением проверки сертификатов. Ключи APNs/FCM перечитываются при перезапуске шлюза.

Для шлюза только с iOS не задавайте FCM-параметры; для Android без iOS удалите четыре параметра идентификации APNs. Сервис отказывается запускаться без настроенного провайдера. Статус `/health/live` проверяет процесс, а `/v1/status` требует токен и возвращает настроенные платформы; доступность Apple/Google и корректность их credentials подтверждает только реальная отправка.

## Подключение семейного сервера

Выдайте отдельный токен каждой установке. Команда сохраняет его в файл 0600 и печатает только идентификатор для последующего отзыва:

```bash
sudo docker compose run --rm -v "$PWD/export:/export" gateway add-client \
  --state /var/lib/familychat-push/state.json \
  --name family-one --token-file /export/family-one.token
```

Передайте файл защищённым каналом администратору сервера чатов, сохраните, например, как `/root/family-one.token` с правами 0600. Адрес и токен можно указать при установке **релиза, включающего эту функциональность**:

```bash
sudo bash install.sh \
  --push-gateway-url https://push.example.com:9443 \
  --push-gateway-token-file /root/family-one.token
```

При первой интерактивной установке адрес также запрашивается; Enter откладывает настройку. На установленном сервере:

```bash
sudo familychat configure-push \
  --push-gateway-url https://push.example.com:9443 \
  --push-gateway-token-file /root/family-one.token
```

Без аргументов `configure-push` предлагает `gateway`, `direct` (прежняя настройка APNs) и `off`. Адрес шлюза должен быть HTTPS origin, без пути/параметров/логина; поддерживаются DNS и IPv4. Токен передаётся файлом, не аргументом командной строки. Установщик проверяет TLS, авторизацию и версию протокола, сохраняет файл 0400 с владельцем UID 10001 и пересоздаёт API/worker. Только worker получает этот файл. Ошибка проверки или Compose config восстанавливает прежний `.env`; если ошибка возникает уже при перезапуске Docker, новые настройки сохраняются для повторного запуска команды.

Переход в gateway отключает прямые APNs/FCM-параметры и их монтирование. Старые файлы ключей автоматически не удаляются: после проверки перенесите их в защищённое хранилище вне сервера чатов. `update`, повторная установка и HTTPS-обслуживание сохраняют override; откат на несовместимый релиз блокируется.

При установке сервера чатов из исходников задайте в его `.env` `PUSH_GATEWAY_URL` и `PUSH_GATEWAY_TOKEN_FILE=./secrets/family-one.token`, установите владельца файла 10001:10001 и режим 0400. Серверный `scripts/deploy-https.sh` подключает override автоматически. Для ручного Compose сервера чатов добавляйте `-f compose.push-gateway.yaml` после основных файлов при **каждом** пересоздании контейнеров.

## Отзыв и ротация

На шлюзе:

```bash
sudo docker compose run --rm gateway revoke-client \
  --state /var/lib/familychat-push/state.json --id CLIENT_ID
```

Отзыв применяется к новым запросам без перезапуска, вместе с удалением регистраций этой установки; уже начатую отправку отозвать нельзя. Для ротации выдайте новый токен, выполните `configure-push` с новым файлом, затем отзовите старый CLIENT_ID. Регистрации устройств восстановятся при отправке.

## Граница доверия и ограничения

- Каждый сервер получает 256-битный случайный секрет; на шлюзе хранится только его SHA-256. Device handles принадлежат конкретной установке; другой токен не может отправить или удалить уведомления по чужому handle.
- **Сервер чатов доверенный для регистрации APNs/FCM-токенов устройств.** Шлюз не выполняет Apple App Attest/Play Integrity и не доказывает, что токен получен от физического владельца. Компрометация серверного токена позволяет зарегистрировать известный злоумышленнику device token и отправлять на него ограниченные уведомления; нужна немедленная ревокация. Не выдавайте credentials анонимно.
- Шлюз принимает только фиксированные события FamilyChat, UUID маршрутизации и состояния звонков. APNs topic, Firebase project, package name и адреса провайдеров задаются оператором. Произвольные URL, тексты и APS-параметры клиент шлюза передать не может. Имена заменяются на `FamilyChat`; текст переписки не отправляется. Это меняет подписи push и первоначального экрана звонка.
- Шлюз видит device tokens, случайные идентификаторы событий и время отправки. Он не является системой E2EE и не хранит историю переписки. Файл состояния содержит device tokens; защищайте его резервные копии.
- 240 авторизованных запросов в минуту на установку; одна доставка обычно использует два. Максимум 1000 регистраций на установку, 10000 на шлюз, 1024 установки, 4 одновременных HTTP-операции на установку и 32 на шлюз. Неактивные регистрации удаляются при обслуживании регистраций через 90 дней. При исчерпании лимитов возвращаются 429/503. Для публичного адреса дополнительно ограничьте подключения на сетевом периметре.
- HTTPS обязателен; редиректы клиента запрещены. Тела запросов ограничены 16 КиБ, ответов — 4 КиБ, исходящие запросы ограничены таймаутом. Ошибки API не содержат payload, секретов или ответов провайдера. Не включайте логирование Authorization/body в промежуточном прокси.
- Шлюз не имеет собственной очереди: используется существующая очередь worker сервера чатов. Ошибки авторизации, сети и провайдера не удаляют device token; удаление происходит только после подтверждённой недействительности токена. Доставка может повториться при потере ответа; истёкшие звонки не пересылаются. Работа в фоне и звонки требуют отдельной проверки на реальных устройствах.
- Файловое состояние и лимиты рассчитаны на один экземпляр шлюза. Не запускайте несколько реплик за балансировщиком. CLI и сервис координируют доступ через файловую блокировку; не размещайте state на NFS.

Для запуска без Docker соберите `go build -o familychat-push-gateway ./cmd/familychat-push-gateway`. Команды `serve`, `add-client`, `revoke-client` те же. Передайте APNs/FCM-переменные окружения процессу, обеспечьте закрытый каталог state 0700 и чтение TLS/provider-файлов сервисным пользователем. Сервису не нужны БД чатов, S3 или ключи переписки.


## Сборка и проверки

Проект использует только стандартную библиотеку Go 1.27.1. Приватные ключи и рабочая конфигурация для сборки и тестов не нужны: тесты используют временные ключи и локальные HTTP-серверы.

```bash
go test -race ./...
go vet ./...
docker compose build gateway
```

GitHub Actions запускается при push в `main`, pull request и вручную через **Actions → Build push gateway → Run workflow**. Сборка создаёт бинарники Linux amd64/arm64, Docker OCI-архив для обеих архитектур и файл SHA256SUMS; результаты доступны в артефакте `push-gateway-build-<commit>`. OCI-архив предназначен для инструментов с поддержкой OCI; для запуска через Docker Compose используйте сборку из исходников выше. Workflow не развёртывает сервис и не требует ключей APNs/FCM.

API совместим с gateway-режимом сервера [FamilyChat](https://github.com/balamutik/familychat-server). В серверном релизе должны присутствовать `PUSH_GATEWAY_URL`, `PUSH_GATEWAY_TOKEN_FILE` и `compose.push-gateway.yaml`.
